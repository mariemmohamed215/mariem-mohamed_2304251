EXPLANATIONS
Q1.1 The insert with Dno=99 is rejected: the foreign key Dno -> department.Dnumber requires an existing department (ERROR 1452).
Q1.2(c) The update is rejected for the same foreign-key reason; the old Dno stays.
Q1.3(b) A department referenced by employees/projects cannot be deleted (ERROR 1451). Order: first move or delete the employees (after their works_on/dependent rows and any super_ssn/mgr_ssn references to them), delete/move the projects, then delete the department.
Q1.3(c) (An empty result prints no table in the client.) DELETE without WHERE removed ALL rows of dependent (the SELECT inside the transaction shows an empty table). ROLLBACK cancelled the transaction, so all the rows came back.
Q1.7 WHERE filters single rows BEFORE grouping (cannot use aggregates); HAVING filters whole groups AFTER grouping (can use COUNT, SUM, ...).
